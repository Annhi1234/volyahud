# VolyaHUD

Кастомний клієнтський PvP-мод на Fabric, зібраний на API 1.21.4 mappings,
з заявленою сумісністю 1.21.1–1.21.11 (див. розділ "Про сумісність з іншими 1.21.x" нижче).

## Що нового у версії 1.2.0

Це версія, у якій полагоджено **справжні поломки**, а не просто додано
фічки. Усі наведені нижче проблеми перевірені за реальним байткодом
Minecraft 1.21.4 (див. `javap` по мапінгах) — тобто це не здогадки, а
підтверджені причини.

### 1. Більше немає «невидимих факелів» під ногами

**Було:** фіча «світло від предмета в руці» ставила в клієнтський світ
справжній ванільний блок `minecraft:light` у позицію гравця. Блок займав
клітинку (→ невидимий факел, який заважав будувати й засаджувати), а коли в
клітинці з'являвся справжній блок — старий код просто «забував» про свій
фейк, і блок `minecraft:light` залишався лежати назавжди, уже невидимий і
вже нездатним нікого заважати.

**Стало:** світло **не торкається світу взагалі**. Ми підміняємо відповідь
рушія блочного світла (`LightEngineMixin` → `LightEngine#getState`): коли рушій
питає «який блок стоїть ось тут?», ми відповідаємо «це `minecraft:light` з
рівнем N». Для рушія це повноцінне джерело світла — він сам порахує
розповсюдження, просвіти та затемнення, рівно як для справжнього факела.

Наслідки:
- у світі **нічого не змінюється** — нуль шансів щось зламати або заблокувати;
- світло не зникає, коли сервер пересинхронізує чанк (блоку, який можна
  затерти, просто немає);
- додано **налаштування «Яскравість світла»** (1–15): можна зробити світло
  м'якшим, щоб воно не «пробивало» так далеко крізь стіни, як справжній факел.

### 2. Панель «Реальна шкода (крит)» тепер працює

**Було:** панель не показувалася **ніколи**. Крит приходить з сервера
пакетом `ClientboundAnimatePacket` (дія 4/5), а мод чекав на
`ClientboundEntityEventPacket`, який для крита сервер не надсилає ніколи.

**Стало:** ловимо правильний пакет у правильному методі
(`ClientPacketListener#handleAnimate`).

### 3. Мітки над гравцями й підписи чанка тепер на правильному місці

**Було:** проєкція світової точки на екран використовувала
`context.matrixStack()` — а це **свіжий (identity) PoseStack**, створений
ванільним рендером, у якому **немає повороту камери**. Через це мітки
гравців і підписи «16 × 16» випадали з екрана або опинялися не там, де
треба, залежно від того, куди ти повертаєш камеру.

**Стало:** проєкція використовує `context.positionMatrix()` — це те, що
ванільний рендер кладе в `ModelViewMat`, тобто повний поворот камери.

### 4. Рельєф на мінімапі та карті тепер правильний

**Було:** `Heightmap` у ванілі приймає **локальні** координати всередині
чанка (він сам маскує їх через `& 15`), а мод передавав **світові**. Тобто
для чанків, що не починаються з 0, рельєф читався з сусіднього стовпця —
мінімапа була «змішана» з сусідніми чанками.

**Стало:** передаються локальні координати, як у ванільного предмета-мапи.

### 5. Меню налаштувань більше не ховає опції за краєм екрана

**Було:** список опцій малювався вниз від верхнього краю екрана, і все, що
не вміщувалося, опинялося **за межами екрана** — при високому GUI Scale або
на маленькому вікні половина опцій ставала недоступною (кнопки не
натискались, підказки не показувались).

**Стало:**
- список **прокручується** колесом миші та кнопками «▲/▼» біля вкладок;
- рядки, яких не видно, навіть не створюються (тож нічого не «з'їжджає»);
- праворуч показується індикатор прокрутки;
- кнопка **«Готово»** завжди внизу екрана, незалежно від довжини списку;
- додано кнопку **«Скинути налаштування»** (у вкладці «Будівництво») —
  повертає всі опції до стандартних, не чіпаючи міток і позначених чанків;
- вкладки перейменовано й скорочено, щоб вони поміщалися на будь-якій ширині;
- рядки, яких не видно, навіть не створюються (тож нічого не «з'їжджає»).

### 6. Дрібні виправлення

- приховування HUD («.») тепер **скидається** при переході в новий світ —
  інакше можна було залишитися з порожнім екраном і не зрозуміти, що мод
  зламався;
- у вкладці «Інше» додано повзунок **яскравості світла**;
- додано `uk_ua`/`en_us` переклади для всіх клавіш.

## Як перевірити, що все працює

1. Закинути `build/libs/volyahud-1.2.0.jar` у папку `mods` (разом з
   Fabric API для 1.21.4).
2. **Невидимі факели:** взяти в руку факел (або ліхтар) і **походити по
   землі** — під ногами не має з'являтися жодного блоку, який можна
   «зачепити»; у F3 або через мод-дебаг світ має бути, а клітинка під
   ногами — вільною для будівництва (постав блок — він має встати на
   місце без зупинки).
3. **Панель шкоди:** вдарити когось у ближньому бою й дочекатися
   критичного удару — має з'явитися «Завдано: N (нік)».
4. **Мітки:** підійти до гравця й подивитися в різні боки (навіть задом
   наперед) — мітка HP/броні має лишатися рівно над його головою.
5. **Мінімапа:** розійтися на 200+ блоків від спавну й подивитися на
   рельєф — мапа має відповідати реальності (раніше була «змішана»).
6. **Меню (K):** відкрити на високому GUI Scale (наприклад 4) — усі
   опції мають бути доступні через прокрутку; перевірити, що вкладки
   не вилазять за край екрана.

## Що робить

- **Своя броня** — сітка 2x2 або один рядок, будь-який нижній/верхній кут, з ручним зсувом по X/Y і опцією "впритул до низу". % міцності тепер малюється прямо поверх іконки, а не під нею — більше нічого не перекриває сусідній ряд.
- **Броня та HP інших гравців** — з'являються над головою гравця в радіусі, з фоном для читабельності; % міцності також усередині іконки, без накладання на HP-рядок.
- **Прев'ю траєкторії кидка** — лінія, поки тримаєш ender pearl/зілля/пляшку досвіду в руці; тепер рахується з інтерпольованим кутом камери (без "відставання" при швидкому повороті) і зупиняється по формі колізії блока, а не тупо "не повітря" (більше не обривається в траві/квітах).
- **Слід за кинутим предметом** — видно, куди він летить, після кидка.
- **PvP-радар** — смужка над хотбаром з'являється, коли хтось поруч, показує напрямок.
- **Бафи цілі** — активні ефекти гравця/моба, на якого дивишся, у лівому верхньому куті, з фоном, сортуванням за часом і коректним "∞" для нескінченних ефектів (раніше міг показувати сміттєві числа).
- **Показ екіпіровки цілі** — предмет в руках гравця, на якого дивишся.
- **Сповіщення про тотем** — текстове сповіщення, коли хтось поруч використав тотем безсмертя.
- **Інфо-панель FPS/координати** — FPS і X/Y/Z (кожна вісь вмикається окремо, наприклад можна лишити тільки висоту) та координати чанка; кут екрана для панелі обирається окремо від броні.
- **Меню налаштувань** (клавіша **K**) тепер розбите на вкладки (Броня / Гравці / Кидки і радар / Інфо-панель / Чат), як в Sodium — кожна опція має підказку при наведенні, замість однієї суцільної стіни з ~20 кнопок.

## Що нового у версії 1.0.1

**Головний фікс (найважливіший):** усі HUD-елементи тепер малюються ізольовано
одне від одного (кожен обгорнутий у власний try/catch у `VolyaHudClient`).
Раніше, якщо ХОЧА Б ОДИН елемент кидав виняток (наприклад через дрібну
розбіжність рендер-API між патчами 1.21.x), ця помилка вилітала з усього
кадру — і всі елементи, що йшли ПІСЛЯ зламаного у списку виклику, просто
переставали малюватись на кожному наступному кадрі, хоча в налаштуваннях
лишались "увімкнені". Ззовні це й виглядало як "частина функцій не працює" /
"броня то з'являється, то ні". Тепер зламаний елемент вимикає сам себе (з
повідомленням у чат і лог), а решта продовжує працювати нормально.

Інші виправлення й додатки:

- **Меню налаштувань (K) більше не вилазить за край екрана.** Раніше ширина
  7 вкладок рахувалась як фіксовані 108px кожна (756px разом) незалежно від
  реального розміру вікна — при вищому GUI Scale чи вузькому вікні частина
  вкладок опинялась за межею екрана й ставала недоступною для кліку. Тепер
  ширина вкладок підлаштовується під реальний розмір вікна.
- **Сітка меж чанка (G)** раніше малювала лише вертикальні "стовпчики" на
  перетинах меж — тепер додано ще й повноцінні лінії по землі вздовж кожної
  межі чанка, тому це справді виглядає як сітка, а не паркан зі стовпів.
- **PvP-радар** тепер показує невеликий трикутний індикатор скраю панелі,
  коли гравець підкрадається ЗЗАДУ (раніше такі гравці просто повністю
  ігнорувались — а це найнебезпечніша сліпа зона в PvP).
- **Мінімапа**: власна позиція гравця тепер — трикутна стрілка, повернута за
  напрямком погляду, замість статичної квадратної цятки без жодної інформації
  про орієнтацію.
- **Новий компас** (вкладка "Інфо-панель" → "Компас"): сторона світу і
  градуси прямо в HUD, без потреби відкривати F3.

## Чесно про тестування

Це середовище розробки без доступу в інтернет, тож тут неможливо реально
скомпілювати мод (немає Java/Gradle з завантаженими Minecraft-мапінгами) —
так само, як і в попередній версії. Усі виправлення в 1.0.1 перевірені
статичним аналізом коду (логіка, порядок викликів, узгодженість
конфіг-полів між `HudConfig`/`ConfigScreen`/HUD-класами, баланс дужок), але
не реальним компілятором. Перша ж збірка через GitHub Actions (push у
репозиторій) покаже, чи все компілюється; якщо впаде — просто скинь мені лог
помилки, як і раніше.

## Що нового в цій версії (1.0.0)

**Знайдені й виправлені баги:**

- **`inventoryPeek` не працював сам по собі.** У `ArmorHud`/`VolyaHudClient` показ екіпіровки цілі був вкладений усередину перевірки `otherPlayersArmorHud` — якщо в меню вмикали ЛИШЕ "Показ екіпіровки цілі" без броні, нічого не малювалось. Тепер це два повністю незалежні тумблери.
- **Порядок слотів у сітці 2x2 своєї броні** був HEAD+LEGS (верхній ряд) / CHEST+FEET (нижній) — шолом поруч зі штаньми виглядало неприродно. Тепер HEAD+CHEST зверху, LEGS+FEET знизу — порядок зверху вниз по тілу, як у ванільному інвентарі.

**Нові фічі:**

- **Сітка меж чанка** (клавіша **G** або вкладка "Будівництво" в меню) — тонкі лінії на кожній межі чанка (кожні 16 блоків) навколо тебе, плюс підпис "16 × 16" прямо на стінах чанка, у якому стоїш. Зручно для рівної забудови.
- **Кордон території/"міста"** (клавіша **H** — показати/сховати, **J** — позначити/зняти поточний чанк, або вкладка "Будівництво") — напівпрозорі жовті стіни рівно там, де закінчується позначена тобою територія. **Чесно:** це НЕ автоматичне читання даних Towny чи іншого серверного плагіна — клієнтський мод фізично не бачить внутрішні дані сервера без спеціального пакета від нього. Тому це ручна система — сам позначаєш свої чанки, і саме вони підсвічуються. Дані зберігаються в `volyahud.json`, окремо для кожного виміру.

## Чесне обмеження

Повний інвентар (беккпек) іншого гравця сервер клієнту **не надсилає** —
клієнт бачить лише броню й предмет в руках (те, що й так рендериться на моделі).
Показати весь інвентар іншого гравця без плагіна на сервері технічно неможливо.

## Як зібрати .jar на GitHub (без локальної Java/Gradle)

1. Створи новий репозиторій на GitHub (наприклад `volyahud`).
2. Залий у нього весь вміст цієї папки (через веб "Add file → Upload files" або `git push`).
3. Онови `"sources"` в `src/main/resources/fabric.mod.json` на свій репозиторій (косметика, необов'язково).
4. У вкладці **Actions** свого репозиторію GitHub сам побачить `.github/workflows/build.yml` і запустить збірку при кожному push.
5. Через 2-5 хв відкрий останній запуск в Actions → розділ **Artifacts** внизу → завантаж zip, всередині готовий `volyahud-1.0.0.jar`.
6. Кидаєш jar у папку `mods` разом з Fabric API 0.119.4+1.21.4 і Fabric Loader 0.19.3+.

## Про сумісність з іншими 1.21.x

`fabric.mod.json` тепер дозволяє завантаження на `>=1.21.1 <=1.21.11`, і код
не використовує нічого версієспецифічного навмисно. Але чесно: код написаний
і не компілювався локально (у цьому середовищі немає інтернету, щоб Loom
міг скачати Minecraft/мапінги) — реальну збірку робить GitHub Actions при
push, як і раніше.

Найбільший ризик для дуже старих/нових патчів у цьому діапазоні:

- **`PearlTrajectory`** малює лінію напряму через низькорівневий `Tesselator`/
  `BufferBuilder`/`RenderSystem.setShader(CoreShaders...)`. Це найчутливіший
  до змін рендер-API мода клас — якщо в котромусь патчі 1.21.x Mojang
  змінював сигнатури цих класів, саме тут найімовірніше буде compile error.
- **`ClientPacketListenerMixin`** (сповіщення про тотем) чіпляється до методу
  `handleEntityEvent` — назва мапиться Mojang-мапінгами і теоретично може
  відрізнятись між патчами.
- Дрібні гетери типу `getViewXRot`/`getEyePosition`/`getCollisionShape` —
  стабільні API, малоймовірно що зламаються, але не 100% гарантія без реальної збірки.

Якщо після push у GitHub Actions збірка на якійсь версії впаде — це буде
конкретна помилка компіляції з назвою класу/методу, яку легко поправити
за 1 рядок. Просто скинь мені лог помилки з Actions.

## Якщо збірка впаде (compile error) в Actions

Найімовірніші місця з неточностями назв методів/класів (писав без доступу до компілятора з mojmap):

- `ClientPacketListenerMixin` — метод `handleEntityEvent` міг називатись трохи інакше в 1.21.4.
- `BuffHud` — `blitSprite`/`MobEffectTextureManager` API іконок ефектів змінювався між версіями 1.21.x.
- `mc.options.hideGui` — можлива інша назва поля.

Скопіюй помилку з логу Actions і скинь мені — поправлю миттєво.

## Локальна розробка (опційно)

Якщо є Java 21 і доступ в інтернет:

```
./gradlew build
```

jar з'явиться в `build/libs/`.
