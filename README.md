# VolyaHUD

Кастомний клієнтський PvP-мод на Fabric, зібраний на API 1.21.4 mappings,
з заявленою сумісністю 1.21.1–1.21.11 (див. розділ "Про сумісність з іншими 1.21.x" нижче).

## Що робить

- **Своя броня** — сітка 2x2 або один рядок, будь-який нижній/верхній кут, з ручним зсувом по X/Y і опцією "впритул до низу". % міцності тепер малюється прямо поверх іконки, а не під нею — більше нічого не перекриває сусідній ряд.
- **Броня та HP інших гравців** — з'являються над головою гравця в радіусі, з фоном для читабельності; % міцності також усередині іконки, без накладання на HP-рядок.
- **Прев'ю траєкторії кидка** — лінія, поки тримаєш ender pearl/зілля/пляшку досвіду в руці; тепер рахується з інтерпольованим кутом камери (без "відставання" при швидкому повороті) і зупиняється по формі колізії блока, а не тупо "не повітря" (більше не обривається в траві/квітах).
- **Слід за кинутим предметом** — видно, куди він летить, після кидка.
- **PvP-радар** — смужка над хотбаром з'являється, коли хтось поруч, показує напрямок.
- **Бафи цілі** — активні ефекти гравця/моба, на якого дивишся, у лівому верхньому куті, з фоном, сортуванням за часом і коректним "∞" для нескінченних ефектів (раніше міг показувати сміттєві числа).
- **Показ екіпіровки цілі** — предмет в руках гравця, на якого дивишся.
- **Сповіщення про тотем** — текстове сповіщення, коли хтось поруч використав тотем безсмертя.
- **Інфо-панель FPS/координати** — FPS і X/Y/Z (кожна вісь вмикається окремо, наприклад можна лишити тільки висоту) та координати чанка; кут екрана для панелі обирається окремо від броні.
- **Меню налаштувань** (клавіша **K**) тепер розбите на вкладки (Броня / Гравці / Кидки і радар / Інфо-панель / Чат), як в Sodium — кожна опція має підказку при наведенні, замість однієї суцільної стіни з ~20 кнопок.

## Що нового в цій версії

**Знайдені й виправлені баги:**

- **`inventoryPeek` не працював сам по собі.** У `ArmorHud`/`VolyaHudClient` показ екіпіровки цілі був вкладений усередину перевірки `otherPlayersArmorHud` — якщо в меню вмикали ЛИШЕ "Показ екіпіровки цілі" без броні, нічого не малювалось. Тепер це два повністю незалежні тумблери.
- **Порядок слотів у сітці 2x2 своєї броні** був HEAD+LEGS (верхній ряд) / CHEST+FEET (нижній) — шолом поруч зі штаньми виглядало неприродно. Тепер HEAD+CHEST зверху, LEGS+FEET знизу — порядок зверху вниз по тілу, як у ванільному інвентарі.

**Нові фічі:**

- **Сітка меж чанка** (клавіша **G** або вкладка "Будівництво" в меню) — тонкі лінії на кожній межі чанка (кожні 16 блоків) навколо тебе, плюс підпис "16 × 16" прямо на стінах чанка, у якому стоїш. Зручно для рівної забудови.
- **Кордон території/"міста"** (клавіша **H** — показати/сховати, **J** — позначити/зняти поточний чанк, або вкладка "Будівництво") — напівпрозорі жовті стіни рівно там, де закінчується позначена тобою територія. **Чесно:** це НЕ автоматичне читання даних Towny чи іншого серверного плагіна — клієнтський мод фізично не бачить внутрішні дані сервера без спеціального пакета від нього. Тому це ручна система — сам позначаєш свої чанки, і саме вони підсвічуються. Дані зберігаються в `volyahud.json`, окремо для кожного виміру.

## Чесне обмеження

Повний інвентар (беккпек) іншого гравця сервер клієнту **не надсилає** —
клієнт бачить лише броню й предмет в руках (те, що й так рендериться на моделі).
Показати весь інвентар іншого гравця без плагіна на сервері технічно неможливо.

## Як зібрати .jar на GitHub (без локальної Java/Gradle)

1. Створи новий репозиторій на GitHub (наприклад `volyahud`).
2. Залий у нього весь вміст цієї папки (через веб "Add file → Upload files" або `git push`).
3. Онови `"sources"` в `src/main/resources/fabric.mod.json` на свій репозиторій (косметика, необов'язково).
4. У вкладці **Actions** свого репозиторію GitHub сам побачить `.github/workflows/build.yml` і запустить збірку при кожному push.
5. Через 2-5 хв відкрий останній запуск в Actions → розділ **Artifacts** внизу → завантаж zip, всередині готовий `volyahud-1.0.0.jar`.
6. Кидаєш jar у папку `mods` разом з Fabric API 0.119.4+1.21.4 і Fabric Loader 0.19.3+.

## Про сумісність з іншими 1.21.x

`fabric.mod.json` тепер дозволяє завантаження на `>=1.21.1 <=1.21.11`, і код
не використовує нічого версієспецифічного навмисно. Але чесно: код написаний
і не компілювався локально (у цьому середовищі немає інтернету, щоб Loom
міг скачати Minecraft/мапінги) — реальну збірку робить GitHub Actions при
push, як і раніше.

Найбільший ризик для дуже старих/нових патчів у цьому діапазоні:

- **`PearlTrajectory`** малює лінію напряму через низькорівневий `Tesselator`/
  `BufferBuilder`/`RenderSystem.setShader(CoreShaders...)`. Це найчутливіший
  до змін рендер-API мода клас — якщо в котромусь патчі 1.21.x Mojang
  змінював сигнатури цих класів, саме тут найімовірніше буде compile error.
- **`ClientPacketListenerMixin`** (сповіщення про тотем) чіпляється до методу
  `handleEntityEvent` — назва мапиться Mojang-мапінгами і теоретично може
  відрізнятись між патчами.
- Дрібні гетери типу `getViewXRot`/`getEyePosition`/`getCollisionShape` —
  стабільні API, малоймовірно що зламаються, але не 100% гарантія без реальної збірки.

Якщо після push у GitHub Actions збірка на якійсь версії впаде — це буде
конкретна помилка компіляції з назвою класу/методу, яку легко поправити
за 1 рядок. Просто скинь мені лог помилки з Actions.

## Якщо збірка впаде (compile error) в Actions

Найімовірніші місця з неточностями назв методів/класів (писав без доступу до компілятора з mojmap):

- `ClientPacketListenerMixin` — метод `handleEntityEvent` міг називатись трохи інакше в 1.21.4.
- `BuffHud` — `blitSprite`/`MobEffectTextureManager` API іконок ефектів змінювався між версіями 1.21.x.
- `mc.options.hideGui` — можлива інша назва поля.

Скопіюй помилку з логу Actions і скинь мені — поправлю миттєво.

## Локальна розробка (опційно)

Якщо є Java 21 і доступ в інтернет:

```
./gradlew build
```

jar з'явиться в `build/libs/`.
