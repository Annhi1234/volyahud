# VolyaHUD

Кастомний клієнтський PvP-мод на Fabric. Починаючи з **1.5.0** підтримуються
три окремі збірки: **Minecraft 1.21.4**, **1.21.11** і **1.20.1**. Кожна збірка
компілюється під власні mappings/API — це не один універсальний jar.

## Що нового у версії 1.5.0

- **Три версії Minecraft в одному релізі.** Окремі jar-файли для 1.21.4,
  1.21.11 і 1.20.1. Функції HUD, карти, броні, авто-закиду/авто-збору та
  конфігів збережені в усіх трьох збірках.
- **Можна вимкнути фон інфо-панелі.** У налаштуваннях, вкладка **Інфо**,
  з'явився перемикач **«Фон інфо-панелі»**. Коли він вимкнений, FPS,
  координати, ping, CPS та інші цифри малюються без темної пластини/рамки —
  лише текст. Це зручно для чистого HUD і для скріншотів.
- **Конфіг мігрує до `configVersion 4`.** Старі налаштування не втрачаються:
  нове поле `infoPanelBackground` отримує безпечний дефолт `true`, тому після
  оновлення фон спочатку виглядає як раніше.
- **1.21.11:** порт на нові API рендера, `Identifier`, `DynamicTexture`,
  атлас `map_decorations`, `KeyMapping.Category` та нові пакети projectile.
- **1.20.1:** порт на legacy-рендер, `ResourceLocation`, старі item/enchantment
  API та Java 17. Мітки на карті малюються кольоровими ромбами, бо в 1.20.1
  немає нового атласу декорацій; позиції, кольори й назви міток збережені.
- Перевірено збірку і запуск клієнта у світі для 1.21.11 та 1.20.1; для 1.21.4
  додатково проходять усі 7 рефлексійних тестів.

### Який jar вибрати

| Minecraft | Java | Файл |
| --- | --- | --- |
| 1.21.4 | 21+ | `VolyaHUD-1.5.0-mc1.21.4.jar` |
| 1.21.11 | 21+ | `VolyaHUD-1.5.0-mc1.21.11.jar` |

Потрібен Fabric Loader і Fabric API відповідної версії. Поклади **лише один**
jar у теку `mods` свого профілю Minecraft.

## Що нового у версії 1.4.0

Це велике оновлення після 1.3.1: компактніша броня інших гравців, два окремі
режими роботи зі скринею та оновлені налаштування.

### Броня інших гравців

- **Видимість до 15 блоків.** Броня над головою противника має окремий ліміт
  дистанції (`Дистанція броні`, за замовчуванням 15 блоків), а не губиться
  серед далеких HP-міток.
- **Компактний базовий розмір.** Блок HP/броні/зброї стартує з масштабу
  `0.85`, а не з величезних слотів 20×20.
- **Плавне зменшення з відстанню.** Близько гравець бачить базовий розмір, на
  15 блоках блок приблизно на третину менший. Це можна вимкнути.
- **Позиція зверху / зліва / справа** від голови гравця, плюс ручні зсуви
  всього блоку по X/Y. Налаштування не дають блоку вилізти за край екрана.
- Усі старі зсуви HP/екіпіровки та зазор між рядками збережені й працюють
  разом із новим масштабом.

### Авто-закид і авто-збір

- **Авто-закид — `Alt+F6`.** Відкрий скриню/бочку, затисни **Shift** і клікни
  ЛКМ або ПКМ по предмету у **своєму інвентарі** — у контейнер перенесуться
  ВСІ такі самі предмети (включно з хотбаром), а не один стек.
- **Авто-збір — `Alt+F7`.** Shift+ЛКМ або Shift+ПКМ по предмету **в скрині**
  забирає в інвентар УСІ такі самі предмети з цього контейнера.
- Режими незалежні: можна увімкнути тільки закид, тільки збір або обидва.
- Працює зі скринею, подвійною скринею та бочкою. Верстак, піч, шалкерова
  коробка та інші меню не перехоплюються.
- Самі клавіші `G`/`X` без `Alt` нічого не роблять — це захист від
  випадкового перемикання в бою. Перепризначити можна в
  **Controls → VolyaHUD**.

### Налаштування та аудит

- Нові повзунки/кнопки для дистанції, масштабу, позиції та зсувів броні.
- Нові тумблери для авто-закиду й авто-збору з підказками.
- Конфіг мігрує до `configVersion 3`: старі налаштування не втрачаються,
  нові поля отримують безпечні дефолти.
- Перевірено збірку, 7 рефлексійних тестів і запуск реального клієнта
  1.21.4.

## Що нового у версії 1.3.1

- **Оновлені підказки в конфігу та README** під нові клавіші.
- **Версія видна в заголовку меню налаштувань** і в лозі запуску.
- Усі 7 перевірочних тестів і запуск гри з реальним клієнтом проходять.

## Що нового у версії 1.3.0

Версія 1.3.0 розширює карту й додає кілька практичних HUD-функцій, не
змінюючи темно-сірий стиль інтерфейсу та не ламаючи старі мітки.

### Карта й мітки

- **Мітки прив'язані до світу/сервера.** Нова мітка, поставлена на карті
  або клавішею `B`, тепер зберігає ключ поточного світу й не з'являється на
  карті іншого сервера. Старі мітки без цього поля залишаються видимими
  всюди — оновлення нічого не «губить».
- **Автоматична мітка смерті.** У місці смерті ставиться червона мітка
  `☠ Смерть`; наступна смерть у тому самому світі/вимірі замінює попередню,
  щоб не накопичувати десятки позначок. Вмикається/вимикається у вкладці
  «Мапа».
- **Сітка чанків на повноекранній карті.** Тонкі лінії кожні 16 блоків
  допомагають планувати будівництво й орієнтуватися щодо меж чанків.
- **Територія на карті.** Позначені чанки «своєї території» підсвічуються
  жовтим overlay просто на карті, без потреби дивитися на 3D-кордон.
- **Кнопка `↗` біля кожної мітки** у бічній колонці центрує карту на ній;
  у підказці видно координати й відстань до мітки.
- **Статус-рядок під курсором** показує світові `X/Z` і поточний масштаб
  (`px/блок`), а не лише центр карти.

### Нові HUD-функції

- **Ping в інфо-панелі.** Затримка з'єднання з сервером у мілісекундах із
  кольором (зелений/жовтий/червоний). Вмикається у вкладці «Інфо».
- **Панель клавіш WASD + CPS.** Компактна панель показує натиснуті `W/A/S/D`,
  пробіл, ЛКМ/ПКМ і кількість кліків за секунду. Кут, зсув і показ CPS
  налаштовуються; за замовчуванням панель вимкнена.
- **Копіювання координат клавішею `I`.** Копіює `X/Y/Z` і вимір у буфер
  обміну та показує повідомлення в чаті.

### Клавіші за замовчуванням

| Дія | Клавіша |
| --- | --- |
| Меню налаштувань | `K` |
| Повна карта | `O` |
| Швидка мітка | `B` |
| Копіювати координати | `I` |
| Позначити/зняти чанк | `J` |
| Сітка чанків | `[` |

**Controls → VolyaHUD**.

## Що нового у версії 1.2.1.3

Це фінальний прохід по карті й тултипу зброї: виправлено причини, через які
карта могла бути чорною/порожньою, а «реальна шкода» не збігалася з тим, що
гра фактично рахує при ударі.

### Карта й мінімапа

- **Ліва половина світу (X < 0) більше не чорна.** У побудові рядка карти
  зсув усередині чанка рахувався як `max(0, -worldX)`; для від'ємних X це
  давало додатне число, цикл не виконувався — і всі стовпчики з X < 0
  залишалися порожніми. Тепер зсув рахується від початку чанка, тож карта
  коректна по обидва боки від нуля.
- **Мінімапа й повноекранна карта більше не псують одна одну.** Вони мали
  спільні scratch-буфери, хоча їхні області різні; часткова перебудова
  могла домалювати рядки однієї карти поверх іншої (смуги/зсуви). Тепер
  кожна текстура має власний набір буферів.
- **Область текстури завжди містить центр карти.** Раніше вирівнювання по
  сітці `SIZE/2` могло лишити гравця поза текстурою (суцільне чорне тло).
  Тепер сітка — 64 блоки, центр завжди на відстані 256–319 блоків від краю,
  чого вистачає навіть найбільшій мінімапі (320 px).
- **Мінімальний зум повноекранної карти враховує цей зсув.** Раніше він
  рахувався від повних 512 блоків, тому на частині позицій права/нижня смуга
  все одно виходила за текстуру. Тепер запас у формулі — гарантовані 190
  блоків (з урахуванням дробового центру й +2 блоків на округлення).
- **Панорама повноекранної карти працює на будь-яку відстань.** Текстура
  будується навколо центру *погляду*, а не гравця, тому при перетягуванні
  карта не стає порожньою за ~256 блоків.
- **Масштаб і обрізання краю точні.** Масштаб рахується один раз дробовим
  числом, а не округлюється на кожному кроці — карта більше не «сіпається»
  і не показує зайвий блок збоку. Мінімальний зум тепер залежить від розміру
  вікна: карта завжди заповнює видиму область і не показує порожні краї.
- **Світлотінь на межі зміненого чанка правильна.** При частковій
  перебудові перефарбовується не лише змінений рядок, а й рядок під ним —
  інакше на стику лишалася стара смуга тіні.
- **Мітки на мінімапі малюються на своїх місцях.** Координати маркерів
  рахувалися відносно панелі, але малювалися в абсолютних координатах
  екрана — усі мітки збиралися в лівому верхньому куті. Тепер передається
  початок панелі, а відсікання йде за її розмірами.
- **Менше мікрофризів і ризику втратити карту.** Чанк позначається
  «брудним» лише коли його дані справді змінилися; кожна текстура (мінімапа
  й повноекранна карта) має власний курсор версії, тому вони більше не
  «з'їдають» зміни одна в одної; черга не губить позначки під час
  перебору; фоновий і синхронний записи `.dat` серіалізуються спільним
  замком (раніше два GZIP-потоки могли зіпсувати файл). Записи тепер ще й
  ідуть через одну чергу з перевіркою покоління світу, тож старий фоновий
  знімок не може записатися після новішого або після очищення/зміни світу.

### Реальна шкода в тултипі

- **Крит рахується точно як у ванільному `Player#attack` 1.21.4.** Крит
  множить лише базову шкоду (`base × 1.5`), а бонус зачарувань додається
  після крита. Попередня формула `(base + чари) × 1.5` завищувала крит.
- **Враховуються всі операції атрибута** (`ADD_VALUE`,
  `ADD_MULTIPLIED_BASE`, `ADD_MULTIPLIED_TOTAL`) у тому ж порядку, що й
  `AttributeInstance#calculateValue`, а не лише `+N damage`.
- **Кеш тултипа не показує старе число** після зміни предмета в руці,
  зачарувань або живого значення `ATTACK_DAMAGE` (Сила/Слабкість).
- **Числа з випадковою складовою детерміновані** (свіжий генератор із
  фіксованим сідом), а від'ємні значення округлюються правильно.

### Дрібниці

- **Від'ємні координати й шкода форматуються з правильним знаком.** Старий
  ручний поділ на цілу/дробову частину перетворював `-1.2` на `0.2`; тепер
  `-1.2`, а маленькі значення на кшталт `-0.1` не втрачають мінус.
- **Бічна колонка міток у повноекранній карті гортається колесом**, а нова
  мітка автоматично прокручується у видиму частину. Раніше при великій
  кількості міток нижні рядки просто не існували.
- **У конфігу підписи не налазять на кнопки** на вузькому вікні: назва
  скорочується з трикрапкою, але поточне значення/статус показується повністю.
  Вкладки при ширині менше 620 px переносяться у два ряди, а кнопки
  прокрутки стають неактивними, коли гортати нікуди.
- **Підкладка відсотка міцності броні більше не коротша за текст** при
  зменшеному шрифті (підкладка тепер масштабується разом із цифрою).
- Тривалість бафів цілі форматується без `String.format` у гарячому шляху.
- Банер тотема тепер клампиться повністю (разом із рамкою й відступами) і
  не вилазить за правий/нижній край екрана.

### Перевірка

- `.\gradlew.bat compileClientJava --console=plain` — збірка проходить.
- `verification/` (7 рефлексійних тестів) — усі перевірки проходять:
  `MapTerrainTest`, `MapNegativeXTest`, `MapIncrementalTest`,
  `MapCaptureIntegrationTest`, `MapShadingTest`, `MapPixelFormatTest`,
  `BulkTransferTest` (вибір слотів для швидкого закиду в скриню/бочку).

## Що нового у версії 1.2.1.2

Це версія-аудит: знайдено й виправлено справжні баги, плюс прибрано
зайву роботу для слабких машин.

### Виправлені баги

- **Мінімапа й повноекранна карта ламали одна одному GPU-текстуру.**
  Обидві реєстрували текстуру під тим самим іменем, а `TextureManager`
  закриває попередню текстуру під тим самим іменем — тобто відкриття карти
  знищувало текстуру мінімапи (і навпаки). Тепер кожна має свою унікальну
  локацію.
- **Текстура карти могла "залишитись" в пам'яті**, якщо гру закрили не
  через кнопку "Готово". Тепер вона звільняється в `removed()` — тобто
  завжди, коли екран закривається.
- **Старі висоти рельєфу "протікали"** між перебудовами картинки (якщо
  чанк зник, могли лишитись висоти від попередньої перебудови) — тепер
  буфер очищається.
- **Масштаб мінімапи був трохи неправильний** (1.97 px на блок замість
  рівно 2) і показував зайвий блок збоку. Тепер масштаб точний, а
  стрілки до міток з'являються строго на тій межі, за якою мітка
  перестає вміщатись.

### Прибрано зайву роботу (важливо для слабких залізячок)

- **Новий чанк більше не перебудовує всю картинку.** Раніше поява
  кожного нового чанка (раз на 2 секунди під час ходьби) запускала
  перечитування 512×512 = 262 144 блоків — тобто ми робили в 1000 разів
  більше роботи, ніж потрібно (новий чанк — це лише 256 блоків). Тепер
  перечитуються тільки змінені рядки.
- **Мітки більше не створюють об'єктів на кожен кадр.**
- **Панель координат більше не використовує `String.format`** (3 рази на
  кадр) — тепер ручне форматування.
- **Список бафів цілі перевикористовується** замість нового на кожен кадр.
- **Ключ виміру більше не створює новий String на кожен кадр.**
- Пам'ять карти: 1 КБ на чанк (20 000 чанків — це лише 20 МБ).

### Як перевірити

1. Закінчити .jar у папку `mods` (разом з Fabric API для 1.21.4).
2. **Мінімапа + карта:** відкрити карту (O) і подивитися на мінімапу — обидві
   мають показувати рельєф (не чорне тло).
3. **Продуктивність:** походити 2-3 хвилини — не має бути мікрофризів
   кожні 2 секунди (коли підвантажувались нові чанки).
4. **Закид у скриню/бочку:** відкрий скриню або бочку, затисни Shift і
   клікни предмет у СВОЄМУ інвентарі — перенесуться всі такі самі предмети
   (з хотбара теж).



Це версія, у якій карта перероблена «до рівня гри» та прибрані лаги.

### 1. Карта тепер справжня — як у ванільній мапі

**Було:** рельєф малювався тисячами окремих квадів через Tesselator, без
жодного світлотіня — тобто це була просто «плита кольорів», зовсім не схожа
на мапу з Minecraft.

**Стало:** рельєф збирається в справжню GPU-текстуру й малюється одним
викликом — рівно так, як працює ванільний предмет-мапа. Використано
**точний ванільний алгоритм** (розкодовано з `MapItem#update` Minecraft
1.21.4):

- палітра кольорів `MapColor` (усі 62 кольори гри);
- **світлотінь рельєфу** — пагорби й западини видно по освітленню, а не
  лише за кольором блоків;
- вода темніє з глибиною (мілка вода світла, глибока — темна).

**ФІКС (карта була повністю чорна й не прогружалась):** область текстури
вирівнювалася по сітці так, що гравець міг опинитися ПОЗА її межами
(наприклад, при X=100 текстура покривала [-512, 0) — тобто гравця в ній
не було, і на екрані було суцільне чорне тло). Тепер область гарантовано
містить гравця.

### 2. Мітки — справжні ванільні маркери

Замість намальованих хрестиків (або «квадратиків») тепер малюються ті самі
спрайти маркерів, що й у грі (`red_marker` / `blue_marker` з атласу
`map_decorations`).

### 3. Інтерфейс — темно-сірий, а не чорний

Фон усіх панелей HUD був майже чорним (`0xC0000000`) — через це весь
інтерфейс виглядав як суцільна чорна пляма. Тепер це темно-сірий
градієнт (`0xF03A3D43` зверху -> `0xF025272C` знизу): панель відчутно
відділяється від гри, але не «світиться» і не губить текст.

### 4. Слоти броні — квадратики хотбара

Раніше використовувалася світла ванільна текстура `container/slot` (18x18) —
вона виглядала як інвентарна комірка. Тепер слоти малюються вручну: 20x20,
темно-сірий квадрат із рамкою й фаскою, як у хотбарі. Це стосується і
власної броні, і екіпіровки інших гравців.

### 5. Прибрано лаги (за audit коду)

- **Тултип зброї** рахувався ЩОКАДРУ (60-360 разів/с) для однакового
  результату — тепер результат кешується й перераховується лише коли
  змінився предмет або атрибут сили;
- **Кордон території** перераховувався на кожному кадрі (близько 850
  хеш-пошуків) — тепер лише коли змінився чанок гравця чи набір
  позначок;
- **Траєкторія кидка** створювала ~280 об'єктів Vec3 на кадр — тепер
  жодних;
- **Мінімапа/карта** більше не малюють тисячі квадів на кадр;
- **Таб-лист** більше не читається по N разів на кадр;
- кеш карти тепер зберігає id кольорів (1 байт) замість ARGB (4 байти) —
  учетверо менше пам'яті та диска.

### 6. Нова фіча: швидкий закид ВСІХ однотипних предметів у скриню/бочку

**Як користуватись:** відкрий скриню, подвійну скриню або бочку, тримай
**Shift** і клацни предмет у **своєму інвентарі** — перенесуться не тільки
предмети з цього слота, а й **усі такі самі предмети з усього твого
інвентаря** (з хотбара теж). Тобто не треба вручну переносити кожен стек:
клацнув один раз — і всі камені/перли/блоки лежать у контейнері.

- Працює зі **скринею, подвійною скринею та бочкою**. Верстак, піч, шалкерова
  коробка тощо — без змін, як у ванілі.
- Shift+клік по предмету **в самій скрині** тепер забирає всі такі самі
  предмети з контейнера (авто-збір, `Alt+F7`). У версії 1.4.0 це вже не
  ванільна поведінка «по одному стеку».
- Стеки **зливаються** правильно: якщо в скрині вже є такий предмет, вони
  об'єднаються, а не замінюють один одного (робить сам сервер, тож нічого
не розходиться).
- Вмикається/вимикається: **Меню (K) -> вкладка "Інше"** або комбінаціями
  `Alt+F6` (закид) і `Alt+F7` (збір).

### Як перевірити

1. Закінчити .jar у папку `mods` (разом з Fabric API для 1.21.4).
2. **Карта (O):** мапа має показувати рельєф із світлотінню (пагорби світліші
   з одного боку, темніші з іншого), а НЕ суцільну чорну пляму.
3. **Мітки:** поставити мітку (ЛКМ) — вона має з'явитися як ванільний
   маркер (червоний або синій), а не як намальований хрестик.
4. **Броня:** слоти під бронею мають виглядати як темно-сірі квадратики
   хотбара (20x20), а фон панелей — бути темно-сірим, а не чорним.

## Що нового у версії 1.2.0

Це версія, у якій полагоджено **справжні поломки**, а не просто додано
фічки. Усі наведені нижче проблеми перевірені за реальним байткодом
Minecraft 1.21.4 (див. `javap` по мапінгах) — тобто це не здогадки, а
підтверджені причини.

### 1. Більше немає «невидимих факелів» під ногами

**Було:** фіча «світло від предмета в руці» ставила в клієнтський світ
справжній ванільний блок `minecraft:light` у позицію гравця. Блок займав
клітинку (→ невидимий факел, який заважав будувати й засаджувати), а коли в
клітинці з'являвся справжній блок — старий код просто «забував» про свій
фейк, і блок `minecraft:light` залишався лежати назавжди, уже невидимий і
вже нездатним нікого заважати.

**Стало:** світло **не торкається світу взагалі**. Ми підміняємо відповідь
рушія блочного світла (`LightEngineMixin` → `LightEngine#getState`): коли рушій
питає «який блок стоїть ось тут?», ми відповідаємо «це `minecraft:light` з
рівнем N». Для рушія це повноцінне джерело світла — він сам порахує
розповсюдження, просвіти та затемнення, рівно як для справжнього факела.

Наслідки:
- у світі **нічого не змінюється** — нуль шансів щось зламати або заблокувати;
- світло не зникає, коли сервер пересинхронізує чанк (блоку, який можна
  затерти, просто немає);
- додано **налаштування «Яскравість світла»** (1–15): можна зробити світло
  м'якшим, щоб воно не «пробивало» так далеко крізь стіни, як справжній факел.

### 2. Панель «Реальна шкода (крит)» тепер працює

**Було:** панель не показувалася **ніколи**. Крит приходить з сервера
пакетом `ClientboundAnimatePacket` (дія 4/5), а мод чекав на
`ClientboundEntityEventPacket`, який для крита сервер не надсилає ніколи.

**Стало:** ловимо правильний пакет у правильному методі
(`ClientPacketListener#handleAnimate`).

### 3. Мітки над гравцями й підписи чанка тепер на правильному місці

**Було:** проєкція світової точки на екран використовувала
`context.matrixStack()` — а це **свіжий (identity) PoseStack**, створений
ванільним рендером, у якому **немає повороту камери**. Через це мітки
гравців і підписи «16 × 16» випадали з екрана або опинялися не там, де
треба, залежно від того, куди ти повертаєш камеру.

**Стало:** проєкція використовує `context.positionMatrix()` — це те, що
ванільний рендер кладе в `ModelViewMat`, тобто повний поворот камери.

### 4. Рельєф на мінімапі та карті тепер правильний

**Було:** `Heightmap` у ванілі приймає **локальні** координати всередині
чанка (він сам маскує їх через `& 15`), а мод передавав **світові**. Тобто
для чанків, що не починаються з 0, рельєф читався з сусіднього стовпця —
мінімапа була «змішана» з сусідніми чанками.

**Стало:** передаються локальні координати, як у ванільного предмета-мапи.

### 5. Меню налаштувань більше не ховає опції за краєм екрана

**Було:** список опцій малювався вниз від верхнього краю екрана, і все, що
не вміщувалося, опинялося **за межами екрана** — при високому GUI Scale або
на маленькому вікні половина опцій ставала недоступною (кнопки не
натискались, підказки не показувались).

**Стало:**
- список **прокручується** колесом миші та кнопками «▲/▼» біля вкладок;
- рядки, яких не видно, навіть не створюються (тож нічого не «з'їжджає»);
- праворуч показується індикатор прокрутки;
- кнопка **«Готово»** завжди внизу екрана, незалежно від довжини списку;
- додано кнопку **«Скинути налаштування»** (у вкладці «Будівництво») —
  повертає всі опції до стандартних, не чіпаючи міток і позначених чанків;
- вкладки перейменовано й скорочено, щоб вони поміщалися на будь-якій ширині;
- рядки, яких не видно, навіть не створюються (тож нічого не «з'їжджає»).

### 6. Дрібні виправлення

- приховування HUD («.») тепер **скидається** при переході в новий світ —
  інакше можна було залишитися з порожнім екраном і не зрозуміти, що мод
  зламався;
- у вкладці «Інше» додано повзунок **яскравості світла**;
- додано `uk_ua`/`en_us` переклади для всіх клавіш.

   Fabric API для 1.21.4).
2. **Невидимі факели:** взяти в руку факел (або ліхтар) і **походити по
   землі** — під ногами не має з'являтися жодного блоку, який можна

5. **Мінімапа:** розійтися на 200+ блоків від спавну й подивитися на

- **Своя броня** — сітка 2x2 або один рядок, будь-який нижній/верхній кут, з ручним зсувом по X/Y і опцією "впритул до низу". % міцності тепер малюється прямо поверх іконки, а не під нею — більше нічого не перекриває сусідній ряд.

- **Показ екіпіровки цілі** — предмет в руках гравця, на якого дивишся.

- **Інфо-панель FPS/координати** — FPS і X/Y/Z (кожна вісь вмикається окремо, наприклад можна лишити тільки висоту) та координати чанка; кут екрана для панелі обирається окремо від броні.

## Що нового у версії 1.0.1

**Головний фікс (найважливіший):** усі HUD-елементи тепер малюються ізольовано
одне від одного (кожен обгорнутий у власний try/catch у `VolyaHudClient`).
Раніше, якщо ХОЧА Б ОДИН елемент кидав виняток (наприклад через дрібну
розбіжність рендер-API між патчами 1.21.x), ця помилка вилітала з усього
кадру — і всі елементи, що йшли ПІСЛЯ зламаного у списку виклику, просто
переставали малюватись на кожному наступному кадрі, хоча в налаштуваннях
лишались "увімкнені". Ззовні це й виглядало як "частина функцій не працює" /
"броня то з'являється, то ні". Тепер зламаний елемент вимикає сам себе (з
повідомленням у чат і лог), а решта продовжує працювати нормально.

Інші виправлення й додатки:

- **Меню налаштувань (K) більше не вилазить за край екрана.** Раніше ширина
  7 вкладок рахувалась як фіксовані 108px кожна (756px разом) незалежно від
  реального розміру вікна — при вищому GUI Scale чи вузькому вікні частина
  вкладок опинялась за межею екрана й ставала недоступною для кліку. Тепер
  ширина вкладок підлаштовується під реальний розмір вікна.
- **Сітка меж чанка (`[`)** раніше малювала лише вертикальні "стовпчики" на
  перетинах меж — тепер додано ще й повноцінні лінії по землі вздовж кожної
  межі чанка, тому це справді виглядає як сітка, а не паркан зі стовпів.
- **PvP-радар** тепер показує невеликий трикутний індикатор скраю панелі,
  коли гравець підкрадається ЗЗАДУ (раніше такі гравці просто повністю
  ігнорувались — а це найнебезпечніша сліпа зона в PvP).
- **Мінімапа**: власна позиція гравця тепер — трикутна стрілка, повернута за
  напрямком погляду, замість статичної квадратної цятки без жодної інформації
  про орієнтацію.
- **Новий компас** (вкладка "Інфо-панель" → "Компас"): сторона світу і
  градуси прямо в HUD, без потреби відкривати F3.

фінального smoke-тесту 1.4.0 окремо перевірено:

- `K` відкриває меню налаштувань, а нові поля броні показують `0,85` і
  `Зменшувати з відстанню` (раніше масштаб округлявся до `0,9`);
- `Alt+F6`/`Alt+F7` перемикають авто-закид і авто-збір та пишуть
  повідомлення в action bar;
- у лозі немає конфліктів клавіш: `G`/`X` більше не зайняті VolyaHUD, тому
  Simple Voice Chat і ванільний Load Toolbar Activator працюють як раніше.

Історичний текст нижче збережений для контексту версії 1.0.1 — тоді локальної
збірки справді не було, і все перевірялося статичним аналізом.

## Що нового в цій версії (1.0.0)

**Знайдені й виправлені баги:**

- **`inventoryPeek` не працював сам по собі.** У `ArmorHud`/`VolyaHudClient` показ екіпіровки цілі був вкладений усередину перевірки `otherPlayersArmorHud` — якщо в меню вмикали ЛИШЕ "Показ екіпіровки цілі" без броні, нічого не малювалось. Тепер це два повністю незалежні тумблери.
- **Порядок слотів у сітці 2x2 своєї броні** був HEAD+LEGS (верхній ряд) / CHEST+FEET (нижній) — шолом поруч зі штаньми виглядало неприродно. Тепер HEAD+CHEST зверху, LEGS+FEET знизу — порядок зверху вниз по тілу, як у ванільному інвентарі.

**Нові фічі:**

- **Сітка меж чанка** (клавіша `[` або вкладка "Будівництво" в меню) — тонкі лінії на кожній межі чанка (кожні 16 блоків) навколо тебе, плюс підпис "16 × 16" прямо на стінах чанка, у якому стоїш. Зручно для рівної забудови.
- **Кордон території/"міста"** (клавіша `]` — показати/сховати, `J` — позначити/зняти поточний чанк, або вкладка "Будівництво") — напівпрозорі жовті стіни рівно там, де закінчується позначена тобою територія. **Чесно:** це НЕ автоматичне читання даних Towny чи іншого серверного плагіна — клієнтський мод фізично не бачить внутрішні дані сервера без спеціального пакета від нього. Тому це ручна система — сам позначаєш свої чанки, і саме вони підсвічуються. Дані зберігаються в `volyahud.json`, окремо для кожного виміру.

## Чесне обмеження

Повний інвентар (беккпек) іншого гравця сервер клієнту **не надсилає** —
клієнт бачить лише броню й предмет в руках (те, що й так рендериться на моделі).
Показати весь інвентар іншого гравця без плагіна на сервері технічно неможливо.

## Як зібрати .jar на GitHub (без локальної Java/Gradle)

1. Створи новий репозиторій на GitHub (наприклад `volyahud`).
2. Залий у нього весь вміст цієї папки (через веб "Add file → Upload files" або `git push`).
3. Онови `"sources"` в `src/main/resources/fabric.mod.json` на свій репозиторій (косметика, необов'язково).
4. У вкладці **Actions** свого репозиторію GitHub сам побачить `.github/workflows/build.yml` і запустить збірку при кожному push.
5. Через 2-5 хв відкрий останній запуск в Actions → розділ **Artifacts** внизу → завантаж zip, всередині готовий `volyahud-1.0.0.jar`.
6. Кидаєш jar у папку `mods` разом з Fabric API 0.119.4+1.21.4 і Fabric Loader 0.19.3+.

## Про сумісність з іншими версіями

Поточна збірка **1.4.0** призначена тільки для **Minecraft 1.21.4** і
`fabric.mod.json` тепер явно вимагає саме `1.21.4`. Це зроблено навмисно:
Fabric-мод компілюється під конкретні mappings і рендер-API, а між 1.21.1,
1.21.4 та 1.21.11 є реальні відмінності. Обіцяти один jar «на всі 1.21.x» —
значить гарантувати збої на частині версій.

Підтримку 1.20.1 та інших 1.21.x варто робити окремими збірками
(Stonecutter або окремі source-set'и), а не розширенням діапазону в
`fabric.mod.json`. Це наступний етап, коли буде потрібно.
